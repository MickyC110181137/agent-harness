# ④ 驗收

> **對應自我介紹第四段**：第四段是驗收，分三層：靜態與單元測試、部署後對實際服務驗證、實機驗證。每項證據都要能指到 log、資料或截圖，不接受一句「已驗證」。全部通過、分支合併、完成文件寫好，票才算結案。

## 驗證入口

harness 根目錄有一支驗證入口腳本，它做兩件事：

1. 跑[一致性驗證器](01-state-and-planning.md#一致性驗證器)。
2. 依 `projects.json` 列出每個 repo 的 gate 命令，以及該 repo 是否在本機檢出。

它**刻意不代跑**各 repo 的 gate：要跑哪幾個取決於本次動了什麼，而且每個都慢。跑工作項 `worktrees` 涵蓋的那幾個。

每個 repo 自己的驗證入口要符合：

- 同一個 repo 有**一個清楚的預設入口**。
- 失敗時非零結束。
- 沒有測試時明確回報 skipped，不假裝通過。

## 三層驗證

三層缺一不可宣告完成。某一層不適用時，**明確記為 skipped 並寫原因**，而不是省略不提。

### 1. 靜態與單元

- 在該 repo 的 worktree 執行預設 gate（lint、靜態分析、單元測試）。
- **baseline 對照**：改動前跑過一次，改動後的結果與它對照。既有失敗要點名，不得混入本次結果。
- 依 repo 規定追加額外 gate（整合測試、原生層測試、UI 自動化流程）；沒有定義時記 skipped。
- **不要只看包裝層的結束碼。** 跨 shell 包裝可能吞掉失敗碼，測試失敗仍回 0。取證據時看測試指令本身的輸出。
- **同一套測試有多種編譯期設定時，每一種都要跑、都要記。** 只記一輪等於漏掉另一種出貨設定。

### 2. 部署後環境

- 把改動部署到測試環境，**對部署後的服務**驗證。
- **不得以本機執行的分支程式碼連線測試環境資料庫代替。** 本機跑的是還沒部署的程式碼，本機通過不代表部署上去那一份會通過。
- 外部系統的回呼（例如 webhook）只有部署後才收得到，這類行為只能在這一層驗。
- 資料庫結構變更依環境邊界規範取得授權後套用，套用前後都要留下唯讀查詢的結果。

### 3. 實機

- 行為變更一律在實機驗證。模擬器與瀏覽器只能驗畫面，驗不了推播、背景執行、鎖屏喚醒與原生層行為。
- **建置前先確認裝置型號與 CPU 架構。** 架構給錯時安裝仍會成功，但一啟動就崩潰，症狀很像程式 bug。
- **解除安裝前先確認裝得回去。** 簽章不同需要先解除安裝，會清除登入狀態，事先要向使用者說明並取得同意。
- **監看 log 時同時過濾成功與失敗訊號。** 只過濾成功訊號時，崩潰會靜默無輸出，看起來像「還在跑」。
- **「結束 App」有不同語意。** 強制停止、背景回收、行程崩潰對系統行為的影響不同；驗「被系統回收後仍能收到通知」時要選對方式。

## 證據規則

### 每項證據至少要有

- 實際執行的命令或操作
- 結果：通過數／失敗數，或具體的 log 行、資料列、截圖檔名、commit hash
- 未驗證或不適用的項目，以及原因

### 不算證據

- 「已驗證」「應該可運作」「看起來正確」
- 沒有實際執行的測試
- agent 對自己成果的敘述

### 範例

> 預設 gate：baseline 210 tests／208 pass／2 skip → 完成後 217 tests／215 pass／0 fail／2 skip，lint warning 數與 baseline 相同。
> 測試環境部署 HEAD `a1b2c3d`；服務 log 第 4821 行 `status=COMPLETED`。
> 實機：`step-3.png`（15:43）顯示匯出完成；log 中搜尋測試用 token 0 筆。
> iOS 實機：**skipped**，本次未改 iOS 原生層且沒有可用裝置。

### 突變驗證

把本次的關鍵改動**暫時還原**，對應的測試必須變紅。這證明測試真的在保護這個行為，而不是不管有沒有改都會綠。

例：「拿掉輸入長度檢查 → 驗證測試紅」、「把錯誤訊息改回直接拋出原始例外 → 『log 不含敏感資料』的測試紅」。

### 副作用檢查

- 驗證後確認沒有動到不該動的資料（例如相關資料表的列數、最後更新時間與驗證前相同）。
- 測試資料依計畫回收；需要還原的資料要還原，不能直接刪除。

## 證據寫在哪

| 時機 | 位置 |
|---|---|
| 進行中 | 工作項的 `evidence`，以 `project` 或 `cross_project` 為 key |
| 結案 | 完成文件的 **Verification Evidence** 一節，分成「靜態與單元」「部署後環境」「實機」「未驗證項目」 |
