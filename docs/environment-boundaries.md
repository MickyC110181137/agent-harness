# 環境與權限邊界

agent 可以寫程式、跑測試、部署到測試環境，但有些操作一旦做錯就無法回頭。這份規範定義 agent **預設能做什麼、需要授權才能做什麼、永遠不做什麼**。

## 三個等級

| 等級 | 範圍 | 規則 |
|---|---|---|
| **可直接做** | 本機、worktree、測試環境的部署與唯讀查詢 | 依各 repo 的操作文件執行 |
| **需逐次授權** | 測試環境的資料寫入與結構變更、任何 production 寫入 | 執行前在對話中寫出要跑的指令，取得使用者明確同意 |
| **永遠不做** | 建立帳號、代輸密碼或付款資訊、把密鑰寫進版控 | **即使使用者授權也不做**，請使用者自己操作 |

## 測試環境

- 資料庫預設只能執行唯讀查詢。寫入類與結構變更類操作需要使用者明確授權。
- 操作需要超出事先約定的範圍（例如別的 schema、別的服務）時，立即停止並回報，不自行擴大。
- 驗證用的測試資料，在計畫中事先寫好回收方式；需要還原的資料要還原，不能直接刪除。

## Production

**Production 預設唯讀。** 所有寫入類操作只能依已登記、未過期的**具名例外**執行。沒有登記的操作，一律回到唯讀。

### 例外登記

每一筆例外是一個獨立的條目，範本如下：

```markdown
### 例外 NNN — <一句話說明>

| 欄位 | 內容 |
|---|---|
| 對應工作項 | `<feature-id>` |
| 授權人與日期 | <誰>，YYYY-MM-DD |
| 到期日 | YYYY-MM-DD（硬性，不得默認續期） |

**背景**：為什麼需要在 production 做這件事。

**授權範圍**（僅限下列各項）：
1. ……
2. ……

**明確不授權**：
- ……
- 以本例外為由推導出任何其他 production 變更行為

**退場檢查點**：做完哪些事之後本例外失效；有哪些東西需要回收。

**執行紀錄**：
- YYYY-MM-DD HH:mm：做了什麼、實際指令摘要、執行前後的唯讀驗證結果。
```

### 規則

- **授權範圍逐項列舉**，沒列到的就是沒授權。
- **「明確不授權」必須寫**，而且最後一條固定是「不得以本例外為由推導出其他行為」。
- **到期日是硬性的。** 到期時工作還沒完成，必須重新取得書面授權，不得默認續期。
- **追加授權**登記為該例外的新一項，並寫上日期。
- **作廢的項目劃線保留**，寫明作廢原因與還原的證據，不刪除——刪掉等於讓下一個接手的人不知道曾經發生過什麼。
- 每一步執行前後都留下唯讀查詢的結果，作為可追溯的證據。

## 機密

- repo 只記錄機密的**使用邊界**（放在哪、誰能用、用在哪一步），不記錄**值**。
- `.env`、私鑰、token、服務帳號金鑰、資料庫傾印一律不進版控。
- 驗證時需要用到的機密，只在命令列帶入，不寫進檔案。
- 需要時向使用者索取，下一個 session 需要時再重新索取。
